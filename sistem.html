Desain sistem

Bagaimana sistem bekerja

Sistem terdiri atas aplikasi penumpang, server, layanan LLM dan VLM, serta dua node ROS 2 pada komputer kendaraan. Navigasi dan kendali memakai sistem yang sudah ada pada mobil riset otonom ITS tanpa perubahan algoritma.

Arsitektur

Aplikasi penumpang

Memilih titik jemput, memesan, bercakap dengan agen, memantau kendaraan di peta, dan menjawab foto bukti.

Server

Mengelola pesanan dan status, meneruskan percakapan ke LLM, menyaring ciri yang tidak pernah diucapkan, dan menjadwalkan pemeriksaan VLM.

Node penghubung

Menetapkan titik jemput sebagai destinasi, mengirim posisi berkala, mendeteksi kedatangan, meminta kendaraan berhenti, lalu mengaktifkan deteksi.

Node deteksi orang

Penyaring awal di sisi kendaraan. Hanya aktif setelah kendaraan tiba, dan hanya mengirim citra berisi orang beserta kotak pembatasnya.

Alur interaksi 19 langkah

Fase 1 · Pemesanan dan pengumpulan ciri
  1. 1Penumpang mengirim pesanan dan titik jemput. aplikasi → server
  2. 2Perintah jemput beserta koordinat titik jemput. server → kendaraan
  3. 3Status: menuju titik jemput. kendaraan → server
  4. 4Status kendaraan diteruskan. server → aplikasi
  5. 5Posisi kendaraan secara berkala. kendaraan → server
  6. 6Perbarui posisi pada peta. server → aplikasi
  7. 7Pesan berisi ciri penumpang. aplikasi → server
  8. 8Riwayat dan konteks sistem. server → LLM
  9. 9Balasan dan ekstraksi ciri dalam JSON. LLM → server
  10. 10Balasan agen setelah disaring. Diulang sampai ciri wajib lengkap. server → aplikasi
Fase 2 · Kedatangan dan identifikasi visual
  1. 11Status: tiba dan berhenti. kendaraan → server
  2. 12Status: mencari penumpang. server → aplikasi
  3. 13Citra dan kotak kandidat dari detektor YOLO. kendaraan → server
  4. 14Citra kandidat bernomor dan ringkasan ciri. server → VLM
  5. 15Keputusan, nomor kandidat, dan alasan. VLM → server
Fase 3 · Konfirmasi dan penyelesaian
  1. 16Status ditemukan dan foto bukti dengan kotak hijau. server → aplikasi
  2. 17Jawaban foto: "Ya, itu saya" atau "Bukan saya". aplikasi → server
  3. 18Konfirmasi penumpang sudah di kendaraan. aplikasi → server
  4. 19Perintah hentikan deteksi. server → kendaraan

Selain menunggu hasil VLM, penumpang dapat meminta foto kamera kapan saja setelah kendaraan tiba. Setiap orang di foto diberi nomor, sehingga penumpang bisa memilih nomor dirinya sendiri dan pesanan langsung terkonfirmasi.

Status kendaraan: SIAGA, MENUJU_TITIK, TIBA, dan OFFLINE. Pesanan aktif gagal bila kendaraan OFFLINE lebih dari 120 detik.

Integrasi dengan navigasi kendaraan

Penjemputan tidak mengubah navigasi atau kendali. Interaksinya hanya melalui tiga hal: menetapkan destinasi, membaca posisi, dan meminta berhenti.

  1. Titik awal tidak perlu dikirim.Perencana rute global mencocokkan posisi kendaraan saat itu ke segmen terdekat (jarak dan arah hadap), lalu mencari urutan segmen ke tujuan dengan algoritma Dijkstra.
  2. Titik akhir berupa koordinat titik jemput.Segmen tujuan adalah segmen terdekat dari koordinat itu. Karena segmen titik acuan GPS disiapkan secara luring, titik jemput harus berada pada jalan yang sudah tercakup segmen.
  3. Posisi dari Kalman Filter.Estimasi posisi dalam koordinat lokal ENU dikonversi kembali ke lintang dan bujur memakai titik acuan GPS saat inisialisasi, lalu dikirim ke server untuk ditampilkan di peta.
  4. Kedatangan dengan jarak haversine.Kendaraan dianggap tiba bila jarak ke titik jemput lebih kecil dari radius kedatangan. Perencana rute bawaan memakai ambang 5 m.
  5. Berhenti sebelum mendeteksi.Kecepatan target nol membuat kendaraan mengerem hingga berhenti penuh. Deteksi baru dijalankan setelah itu agar citra tidak kabur dan posisi orang tidak berubah di antara dua panggilan VLM.

Saluran resmi untuk mengirim kecepatan nol ke sistem kendali masih perlu dipastikan bersama tim mobil riset sebelum uji lapangan. Tahap ini menyangkut keselamatan.

Pencocokan VLM

Satu panggilan untuk semua kandidat

Setiap orang hasil YOLO diberi kotak dan nomor. VLM menerima satu citra berisi seluruh kandidat beserta ringkasan ciri, lalu menjawab keputusan, nomor kandidat, dan alasannya dalam JSON terstruktur.

Mode masking dan bingkai penuh

Mode masking menghitamkan area di luar kotak kandidat tetapi mempertahankan posisi relatifnya. Mode bingkai penuh mengirim citra apa adanya, berguna bila ciri posisi bergantung pada objek sekitar.

Kandidat yang sudah ditolak

Orang yang dijawab "Bukan saya" tidak dikirim lagi bila masih di tempat yang sama (kotak tumpang tindih ≥ 0,5). Bila sudah berpindah, deskripsinya dikirim sebagai orang yang bukan penumpang.

Mengapa tidak memakai skor kemiripan

Pada uji metode rujukan, kandidat berjaket hitam mendapat skor 0,88 sedangkan kandidat berjaket merah 0,83 untuk deskripsi "jaket merah". Karena itu penelitian ini meminta VLM menalar semua kandidat secara langsung.
